# 多言語対応 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 画面の文字を日本語・英語・スペイン語・中国語（簡体字）・韓国語で出し、タイトル画面で切り替えられるようにする。

**Architecture:** コード中の日本語の文そのものを鍵にして、表示の直前に `T(ja, vars)` で訳を引く（訳がなければ日本語）。HTML は `data-i18n` を付けた要素の中身を起動時に日本語として覚えて差し替える。訳は言語ごとに `src/text-xx.js` の辞書に置く。

**Tech Stack:** 素の JavaScript（ES modules）、node:test、追加ライブラリなし。

**Spec:** `docs/superpowers/specs/2026-11-19-i18n-design.md`

## Global Constraints

- 言語：`ja`（日本語）`en`（English）`es`（Español）`zh`（简体中文）`ko`（한국어）。ボタンにはそれぞれ自分の言葉での名前を出す
- `sim.js` に言語の処理を入れない。言語によって試合の結果が変わらない
- ビルドは import/export を取り除いて連結する。新しいファイルの最上位の名前は全 `src/` で重複させない。新しいファイルは `tools/build.mjs` の `ORDER` に足す（`i18n` と辞書は `config` の次）
- キャラ名はローマ字（カガリ → Kagari）。技名は訳す。超必殺の帯は漢字の技名を大きく、訳を小さく添える（日本語のときは今のまま）
- 擬音（パシッ ビシッ バキッ ドカッ ドゴォ ズガッ ズドン ゴォッ ガッ ドン ドカン あちっ）はカタカナのまま。意味を伝える文字（カウンター 投げ抜け 耐えた ガード崩し ジャスト！ よろけ 突風 分身 返し 弾いた 最大：ガード崩し 最大：ガード不能 毒 受け流し 連撃 ダメージ 超 練習 など）は訳す
- 中国語・韓国語のときだけ Google Fonts の Noto Sans SC / Noto Sans KR を `<link>` で足す（今の CSP の範囲）
- 選んだ言語は `localStorage` の `rengeki-lang`。読み書きは try/catch（失敗しても動く）
- `tools/` の道具・宣伝動画・アイコンは変えない

## Review Focus

- `localStorage` が使えない（プライベートブラウズ）→ 端末言語で動き、切り替えもその場では効く（Task 1 のテスト）
- 端末言語が対象外や地域付き（`fr`、`pt-BR`、`zh-TW`、`ko-KR`、`es-419`）→ `ja*`→ja、`zh*`→zh、`ko*`→ko、`es*`→es、それ以外→en（Task 1 のテスト）
- キャラ選択・ステージ選択の札を作った後で言語を変える → 札の文字も変わる（Task 2 で `onLangChange` を使い作り直す。Task 5 で画面確認）
- オンラインで2人の言語が違う → 試合は同じ（Task 4 の `stateHash` テスト）
- スペイン語の長い文がスマホ横向き（812×375）のボタン・帯・結果表からはみ出す（Task 5 で画面確認して直す）

### Task 1: 翻訳の仕組み（`src/i18n.js`）

**Files:**
- Create: `src/i18n.js`, `src/text-en.js`, `src/text-es.js`, `src/text-zh.js`, `src/text-ko.js`（辞書はこの時点では空の `{}`）
- Modify: `tools/build.mjs`（`ORDER` の `'config'` の直後に `'text-en', 'text-es', 'text-zh', 'text-ko', 'i18n'`）
- Test: `tests/i18n.test.mjs`、`package.json` のテスト一覧に追加

**Interfaces:**
- Produces:
  - `LANGS: [{ id: 'ja', label: '日本語' }, { id: 'en', label: 'English' }, { id: 'es', label: 'Español' }, { id: 'zh', label: '简体中文' }, { id: 'ko', label: '한국어' }]`
  - `pickLang(list: string[]): string` … 端末の言語一覧から決める（規則は Review Focus の通り。最初に当てはまったもの）
  - `T(ja: string, vars?: object): string` … 今の言語の訳、なければ `ja`。`{name}` を `vars.name` で置き換える（訳がなくても置き換える）
  - `getLang(): string`、`setLang(id: string): void`（保存し、`onLangChange` の登録先を呼ぶ）、`onLangChange(fn): void`
  - `I18N_DICTS: { en: TEXT_EN, es: TEXT_ES, zh: TEXT_ZH, ko: TEXT_KO }`（テストが使う）
  - `applyDom(root: Element): void` … `[data-i18n]` の innerHTML、`[data-i18n-label]` の `aria-label`、`[data-i18n-ph]` の `placeholder` を、初回に覚えた日本語から `T` で差し替える。`<html lang>` を更新。zh/ko なら字体の `<link>` を1回だけ足し、`--body` / `--display` の先頭に Noto Sans SC/KR を足すクラス（`html.lang-zh` / `html.lang-ko`）を付ける
  - 起動時の言語：保存値 → なければ `pickLang(navigator.languages)`。`document` がない環境（node のテスト）でも import できること

- [ ] **Step 1: 失敗するテストを書く**（`tests/i18n.test.mjs`）
  - `pickLang(['fr'])==='en'`、`pickLang(['pt-BR','es-419'])==='es'`、`pickLang(['zh-TW'])==='zh'`、`pickLang(['ko-KR'])==='ko'`、`pickLang(['ja-JP','en'])==='ja'`、`pickLang([])==='en'`
  - `setLang('ja'); T('勝利！')==='勝利！'`
  - 辞書に一時的に `TEXT_EN['テスト{n}回'] = 'test {n} times'` を足し、`setLang('en'); T('テスト{n}回',{n:3})==='test 3 times'`、`T('未訳の文{n}',{n:1})==='未訳の文1'`
  - `localStorage` がない node 環境で `setLang('ko'); getLang()==='ko'` が例外なしで通る
- [ ] **Step 2: `npm test` で失敗を確認**（`i18n.js` がない）
- [ ] **Step 3: 上の Interfaces どおりに実装**
- [ ] **Step 4: `npm test` が全部通る、`npm run build` が通る**

### Task 2: 画面の文字を `T` と `data-i18n` に通す

**Files:**
- Modify: `index.html`（日本語のある要素すべてに `data-i18n`、`aria-label` に `data-i18n-label`、入力欄に `data-i18n-ph`。タイトルの `.title-sub` に言語ボタン `#btn-lang`）
- Modify: `src/main.js`（日本語の文字列をすべて `T(...)` で包む。テンプレート文字列は `T('{name}の勝ち', { name })` の形に。`GUIDE_STEPS` は表示時に `T`。`stageCard`・キャラの札・技表・結果表も。起動時に `applyDom(document.body)`、`onLangChange` で `applyDom` と、作った札の文字・ボタン表示（音・全画面・ギミック）を更新）
- Modify: `src/net.js`（`onFail` とエラーの文を `T`）
- Modify: `src/render.js`（`pushText` の意味のある文字、試合の帯、`連撃`・`ダメージ`・`超`・`練習`・勝利の帯を `T`。ステージの `name` は使っている所で `T`）
- Modify: `styles.css`（`html.lang-zh` / `html.lang-ko` の字体）

**Interfaces:**
- Consumes: Task 1 の `T` `applyDom` `onLangChange` `LANGS` `getLang` `setLang`
- Produces: 画面の日本語はすべて `T('…')`（第1引数が文字列リテラル）か `data-i18n*` の要素に入っている。Task 4 のテストはこの2つと、キャラ・ステージのデータを鍵として集める
- 言語ボタン：押すと `LANGS` を順に回す（表示は今の言語の `label`）。`playSound('ui')`

- [ ] **Step 1: 失敗するテストを書く**
  - `test('全部の文に4言語の訳がある')`：鍵を集める＝`src/*.js` の `T('…')` / `T("…")` / `` T(`…`) ``（第1引数のリテラル）＋ `index.html` の `data-i18n` 要素の中身（`<(\w+)[^>]*\sdata-i18n[^>]*>([\s\S]*?)</\1>`、前後の空白を詰める）と `data-i18n-label` / `data-i18n-ph` の値＋全キャラの `name` `title` `style`、全技の `name` と `hint`、`SPECIAL_COMMANDS` の説明、全ステージの `name` `note`。各言語の辞書に無い鍵を一覧にして、空であることを確かめる（失敗時は抜けた鍵が見えるように）
  - `test('差し込みの名前が日本語と訳で一致する')`：各鍵の `{…}` の集合と、各訳の `{…}` の集合が同じ
  - `test('辞書に使われていない鍵がない')`：辞書の鍵がすべて集めた鍵に含まれる（古い訳の残りを防ぐ）
  - `test('言語を変えても試合は同じ')`：`setLang('ja')` と `setLang('es')` それぞれで `createMatch({ p1:'kagari', p2:'hayate', stage:'storm', gimmicks:true })` を CPU（`createCpu('hard',3)` と `createCpu('normal',4)`）で1500コマ進め、`stateHash` が等しい
