# レートとランキング（Google ログイン）設計

## なぜ
海外で流行るオンラインゲームにする計画の一部。オンライン対戦の結果で強さの数値（レート）を付け、ランキングで競えるようにする。あとで作る「ガチャ」「課金」も同じログインの上に乗るので、ここでアカウントの土台も作る。

## 目標
- Google でログインできる。一度ログインしたら、ログアウトするまでずっとログインしたまま（本人の希望）
- ランダム対戦の結果でレートが上下する。試合後の結果画面に「+16（1516）」のように出る
- タイトルからランキング画面を開ける。上位100人と、自分の順位・レートが見られる
- ログインしなくても、今まで通り全部遊べる（CPU・2人対戦・練習・部屋対戦・ランダム対戦）。レートが付かないだけ

## やらないこと
- ガチャ・課金・シーズン（期間ごとのリセット）・フレンド機能
- レートの近い人どうしを優先して組ませること（人が少ないうちは待ち時間が延びるだけ。人が増えたら考える）
- Google 以外のログイン（Apple・X など）

## 失敗とみなすこと
- 本名・メールアドレスが他の人に見える
- 1台の端末（改造したゲーム）だけで、勝ちをでっち上げたり、他人のレートを下げたりできる
- 友だちと示し合わせた八百長で簡単にレートを稼げる
- ログインしないと遊べなくなる

## 作り方の候補（決定済み）
1. **Google ログイン（採用、本人が選択）**：機種を変えても続きから。なりすましに強い。Google 側の設定が本人の作業として要る
2. 名前を入れるだけ（端末が覚える）：手軽だが、記録を消すと別人になり、ズルにも弱い

## 決めたこと
- **ログイン**：Supabase Auth の Google ログイン（PKCE 方式）。ログイン状態は端末に保存され、自動で延長される（本人の希望：基本ログインしっぱなし）
- **表示名**：初めてログインした時に、ランキングに出す名前（2〜12文字）を自分で決める。Google の名前やメールは使わない・見せない。あとから変えられる（Claude の判断：海外の人も多いので、本名が出るのを避ける）
- **レートが付く試合**：ランダム対戦で、2人ともログインしている時だけ。部屋コードの対戦は付かない（友だちどうしの八百長を防ぐ）。同じ相手との試合は1日5回まで数える（Claude の判断）
- **レートの計算**：Elo 方式。初期 1500、最初の20試合は K=40（早く実力に近づく）、その後 K=24。最低 100（Claude の判断）
- **結果の記録（ズル対策）**：計算はすべてサーバー（Supabase のデータベースの関数）で行う
  - 試合が始まった時、2人それぞれが「この部屋・この試合番号で、この相手と始めた」とサーバーに届ける。2人分そろった試合だけがレートの対象
  - 試合が終わったら、2人それぞれが結果（勝ち・負け・引き分け）を届ける。2人の報告が一致したら、その時にレートを動かす（1試合につき1回だけ）
  - 食い違ったら、レートは動かさない
  - 片方しか報告しない（負けそうな人が閉じた・回線が切れた）まま10分たったら、報告した側の結果を採用する（途中で逃げても負けを避けられない）
  - 2人とも「相手が切れた」と報告した時は、レートは動かさない
- **ランキング**：上位100人（名前・レート・勝ち数・試合数）と自分の順位。1試合もしていない人は載せない
- **個人情報**：サーバーに置くのは、Supabase のログイン記録（Google から受け取るメールなど。Supabase の仕組みが持つ）と、表示名・レート・成績だけ。「プライバシー」のページ（日本語・英語）を作り、何を保存しているかと消し方を書く。アカウントの画面に「アカウントを削除」を置く（成績も含めて全部消える）
- **通信の節約**：supabase-js はログインしている人・ログインする時・オンライン対戦の時だけ読み込む（ゲストは今まで通り読み込まない）
- **訳**：新しい文は4言語の訳も付ける（今の多言語の仕組みのまま）

## 仕組み（ビルダーへの指示）
- サーバー（Supabase の Postgres、`apply_migration` で作る）
  - `profiles`：id（ログインした人）・表示名・レート・試合数・勝ち数・作った日。誰でも読めるのは表示名・レート・成績だけ
  - `match_starts`・`match_reports`：部屋名・試合番号・本人・相手・結果・時刻
  - `rated_matches`：レートを動かした試合の記録（同じ試合を2回数えないため）
  - 書き込みは全部、本人確認（`auth.uid()`）をする関数（`security definer`）から。表に直接は書けない（RLS）
  - 10分たった片方だけの報告の確定と、古い記録の掃除は `pg_cron` で数分ごと
- ゲーム
  - ログイン・ログアウト・表示名・アカウント削除・ランキングの画面（タイトルに「ランキング」と、アカウントの小さいボタン）
  - 部屋で出会った時に、お互いのログインの id を交換する（ランダム対戦の時だけ）
  - 試合開始と結果の報告。報告は失敗しても試合には影響しない（数回まで送り直す）
  - 結果画面にレートの変化を出す
- 本人の作業：Google Cloud で OAuth の設定（同意画面・クライアント ID とシークレット）、Supabase の「Authentication → Providers → Google」に入れる、「URL Configuration」に本番のアドレスを入れる。鍵はチャットに貼らない
- テスト：Elo の計算、報告の一致・食い違い・片方だけ・切断の扱い、同じ相手の回数制限、ゲストとの試合はレートなし。サーバーの関数は Supabase 上で実際に呼んで確かめる

## ビルダーに任せること
- 画面の見た目（今の画面に合わせる）、文言
- 報告の送り直しの回数と間隔
- ランキングの読み込みの細かい作り
