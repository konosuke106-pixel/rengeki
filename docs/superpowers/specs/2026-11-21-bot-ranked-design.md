# ランクマッチの Bot（レートが動く）設計

## なぜ
試験公開の最初は遊ぶ人が少なく、ランクマッチで「相手を探す」を押しても人に当たらない。Bot を10体ほど用意して、すぐ試合ができ、レートとランキングが最初から動いて見えるようにする（本人の希望）。Bot との試合でもレートは動かす（本人が選択）。

## 目標
- ランクマッチで10秒たっても人が見つからなければ、レートの近い Bot と当たる（今の「30秒で CPU 戦」を置きかえる）
- 対戦前に「BOT ゲン（レート1500）と対戦」のように、Bot だと分かる形で出す
- 勝てばレートが上がり、負ければ下がる（人との試合と同じ Elo、Bot のレートを相手として使う）
- ランキングに Bot も「BOT」の印つきで載る
- ログインしていない人も Bot と遊べる（レートは付かない）

## やらないこと
- Bot を人間のように見せること（名前に必ず BOT の印。人のふりは信用を失い、ストアやサービスの決まりでも問題になる）
- Bot のレートを動かすこと（決まった値。強さの目安としてずっと同じ位置にいる）
- 人との試合の仕組みの変更

## 失敗とみなすこと
- 改造したゲームが「Bot に勝った」と嘘をついてレートを稼げる
- 試合の途中で閉じれば負けを避けられる
- ゲームを更新したあと、サーバー側の再生と中身がずれて、正しく遊んだ人の勝ちが負けにされる
- Bot が人だと誤解される

## 作り方の候補
1. **サーバーで試合を再生して勝ち負けを決める・Supabase の Edge Functions（採用）**：同じ操作なら必ず同じ結果になる作りを生かす。1試合の再生は普通6ミリ秒・長くて31ミリ秒（測定）で、上限2秒に十分収まる。無料
2. 同じ再生を Cloudflare Pages Functions で：サイトの公開と同時に必ず同じ中身になる利点があるが、無料では1回10ミリ秒までで足りない（有料月5ドル）
3. ゲームの報告をそのまま信じる：ズルを防げないので不採用

## 決めたこと
- **Bot**：10体。名前（完全オリジナル）・得意キャラ1人・CPU の強さ（easy / normal / hard）・決まったレート（1100〜1850くらいに散らす）を持つ。サーバーの表に置く（Claude の判断：名前と細かい数値はビルダーが決め、レートはその強さで人が勝てる割合に合わせて大まかに決める）
- **試合の始め方**：ランクマッチで人が10秒見つからない → サーバーに「Bot 戦を始めたい」と聞く → サーバーが自分のレートに一番近い Bot（同じ Bot が続かないよう近い3体から順番）と、乱数の種と試合の番号を返す → 自分のキャラを選ぶ（Bot のキャラは決まり）→ ステージは Bot のキャラのステージ、ギミックあり（オンラインと同じ）
- **試合中**：普通の CPU 戦と同じく手元で動かす。Bot は `createCpu(Bot の強さ, 種)`。自分の入力を毎コマ記録する。一時停止はコマが進まないので記録に影響しない
- **結果の届け方**：決着したら、試合の番号・版（`NET_VERSION`）・自分のキャラ・入力の記録（毎コマの押しボタン。同じ値が続く所はまとめて小さくする）をサーバーへ送る
- **サーバーの確認**（Edge Function `bot-match`）：記録をもとに同じ試合を最初から再生し、勝ち負けを決める。版が違う・記録が壊れている・試合が終わらない（最大 21600 コマ）時はレートを動かさない。決まった結果でレートを動かし（Bot 側は動かない）、新しいレートと変化を返す
- **ズル・逃げ対策**：種は試合を始める時にサーバーが決める。1試合につき結果は1回だけ。試合を始めて20分たっても結果が届かなければ負け扱い。同じ Bot との試合は1日5回まで数える。報告のもめごとが多い人（今の `too_disputed`）は Bot 戦でも対象外
- **ゲームの更新とのずれ**：サーバー側の再生に使う中身（戦闘・キャラ・ステージ・CPU）は、`main` に push すると GitHub Actions が自動で Edge Function を更新する。そのため本人に一度だけ Supabase のアクセストークンを GitHub の秘密の設定に登録してもらう（チャットに貼らない）。版が違う間は Bot 戦のレートを動かさず、結果画面に「Bot 戦のレートは更新中のため今回は動きません」と出す
- **数え方**：Bot 戦も人の試合数・勝ち数に入る。K は人と同じ（自分の試合数20未満は40、以後24）。同じ Bot との6試合目からはレートを動かさず、試合数にも入れない
- **版の印**：今の版の印（`NET_VERSION`）はゲームのコード全体から作るので、画面だけの変更でも変わる。GitHub Actions はビルドして版の印を計算し、それを Edge Function に埋め込んで更新する。サイト（Cloudflare）とサーバー（Supabase）の更新が終わる時刻は少しずれるので、その間の Bot 戦はレートなしになる（許容）
- **ゲストとログインしていても名前がない人**：Bot と遊べるが、サーバーには何も送らない（レートなし）
- **表示**：対戦前の帯と結果画面とランキングに「BOT」の印。結果画面は人との試合と同じく「レート +12（1512）」

## 仕組み（ビルダーへの指示）
- サーバーの表：`bots`（id・名前・キャラ・強さ・レート）、`bot_matches`（試合の番号・人・Bot・種・始めた時刻・結果・レートの変化）。直接は読み書きできず関数だけ（今の作りと同じ）
- 関数：`start_bot_match()`（ログイン＋名前ありの人だけ。Bot と種と番号を返す。1時間60回まで）、ランキングの関数は Bot も含めて返す（BOT の印つき）、`finalize_stale` に「20分たった Bot 戦は負け」を足す
- Edge Function `bot-match`：ログインの確認、試合の番号の持ち主の確認、再生、レートの更新（サーバーの関数を通す）
- 再生用の中身：`src/config.js` `characters.js` `stages.js` `sim.js` `ai.js` をそのまま使う（`sim.js` と `ai.js` には乱数や時刻を入れない約束が今もある）。版の印はビルドと同じ作り方で計算する
- テスト：記録の圧縮と復元、再生した勝ち負けが手元と一致すること（全キャラ）、版違い・壊れた記録・二重送信・20分の負け・1日5回・ゲストは送らない。サーバーの関数は今と同じく `supabase/tests` で

## ビルダーに任せること
- Bot の名前・キャラ・強さ・レートの細かい値、選び方の細部
- 入力の記録の詰め方
- 画面の文言と見た目（今の画面に合わせる）
- 本人へのアクセストークン登録の案内（画面に合わせて、できる所は操作も手伝う）
